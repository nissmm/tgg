# HR-бот

Бот на aiogram 3 для приёма HR-заявок и уведомлений в топик канала/группы,
с профилями HR, сменами, планом и самозаписью кандидатов с модерацией.

## Структура проекта

```
.
├── .env                  # реальные секреты (не коммитить)
├── .env.example          # шаблон без секретов
├── .gitignore
├── .dockerignore
├── Dockerfile
├── docker-compose.yml
├── requirements.txt
├── main.py               # точка входа
├── config.py             # загрузка переменных окружения
├── storage.py            # хранение данных в бинарных (pickle) файлах в data/
├── filters.py            # проверка "админ канала" / "роль HR"
├── states.py             # состояния FSM
├── keyboards.py          # inline-клавиатуры
├── formatting.py         # хелперы форматирования (даты, прогресс-бар, шаблоны)
├── data/                 # создаётся и заполняется автоматически
└── handlers/
    ├── common.py          # /start, главное меню, отмена
    ├── admin.py           # админ-панель
    ├── hr.py               # запись кандидатов, профиль HR, смены
    ├── self_apply.py       # самозапись кандидатов
    ├── moderation.py       # одобрение/отклонение самозаписи
    ├── records_edit.py     # список и редактирование записей (HR/админ)
    └── topics_listener.py  # обнаружение топиков форума
```

## Установка

```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`.env` уже заполнен вашими данными (токен бота и id канала). Если понадобится
развернуть бота с другими данными — используйте `.env.example` как шаблон.

## Запуск

```bash
python main.py
```

## Запуск в Docker

```bash
docker compose up --build -d
```

`docker-compose.yml` поднимает один сервис `bot`, переменные окружения
берутся из `.env` (`env_file`), папка `data/` монтируется томом, чтобы
данные не терялись при пересборке контейнера.

## Права и топики

**Права.** Админ-панель доступна тем, кто является администратором/создателем
целевого канала-группы (проверяется через Bot API `get_chat_member`, с
кэшем на 5 минут и таймаутом 5 секунд на сам запрос, чтобы недоступность
Telegram не подвешивала кнопки). Роль **HR** выдаётся отдельно, через
админ-панель, и не связана с правами в Telegram.

**Выбор топика.** Telegram Bot API не предоставляет метод, который вернул бы
список всех топиков форума заранее — это ограничение самого API, обойти его
нельзя. Бот запоминает топик, как только видит в нём любое сообщение (или
служебное сообщение о создании топика). После того как в нужном топике
кто-то напишет хотя бы одно сообщение, он появится в списке в админ-панели
(«📌 Выбрать топик для уведомлений»).

## Админ-панель

- **👤 Пользователи** — обычным сообщением (не Rich Message) выводит список
  всех, кто писал `/start`, в формате `@username - 123456789`. Если
  пользователей ещё нет — «Пока никто не писал боту /start.».
- **➕/➖ Назначить / снять роль HR**, **👥 Список HR** — список пользователей
  выводится с id в моноширинном формате (тап = копирование в Telegram),
  затем бот запрашивает id для действия.
- **📊 Таблица записей HR** — отправляется как
  [Rich Message](https://core.telegram.org/bots/api#rich-messages) (Bot API
  10.1, `InputRichMessage` с HTML-разметкой `<table bordered striped>`) —
  таблица с рамками и полосатой заливкой, колонки: «Кто записал», «Кого и
  сколько лет», «Телефон», «Юз», «Дата и время собеса». Кнопки фильтров
  (все / сегодня / неделя / месяц) остаются под таблицей и переключают её
  через `editMessageText(rich_message=...)`. В таблицу попадают только
  подтверждённые записи (не заявки на модерации).
- **✏️ Все записи** — список всех записей с пагинацией, клик → карточка →
  выбор поля → новое значение с той же валидацией, что при создании. Если
  запись уже опубликована в канале, то сообщение там тоже обновляется.
- **🛎️ Заявки на модерации** — список самозаписей кандидатов, ожидающих
  подтверждения.
- **🎯 План на день** — общее целевое число записей в день на всех HR;
  используется в профиле и логе закрытия смены.

## HR-панель

- **➕ Записать нового кандидата** — пошаговый опрос с валидацией:
  1. Кого и сколько лет — в тексте должно быть число.
  2. Номер телефона — обязательно начинается с `+`, формат `+79991234567`.
  3. Юзернейм кандидата — формат `@username`, либо `-`, если юзернейма нет
     или он неизвестен (можно дозаполнить позже через редактирование).
  4. Дата и время собеседования — `ДД.ММ.ГГГГ ЧЧ:ММ` (например
     `25.05.2026 14:00`), дополнительно проверяется, что такая
     дата/время существуют (`strptime`).

  Кто именно записал кандидата, бот **не спрашивает** — привязывается
  автоматически к тому, кто нажал кнопку (`hr_id`, `hr_username`). Это
  сознательное изменение по сравнению с более ранней версией: без этого
  статистику по конкретному HR посчитать невозможно.

- **✏️ Мои записи** — список и редактирование только своих записей
  (по тем же полям и с той же валидацией).

- **👤 Мой профиль** показывает:
  - сколько всего записал (только подтверждённые записи);
  - время последней записи;
  - дату присоединения к роли HR;
  - статус и длительность смены;
  - прогресс по плану на день в виде шкалы (`▓▓▓▓▓░░░░░ 5/10 👍`);
  - заглушку под визуал по рангам — сознательно отложено, добавим отдельно,
    когда будет понятна сама система рангов.

- **🟢 Начать смену / 🔴 Закончить смену.** При завершении смены бот
  считает отработанное время и число записей за смену и публикует итог
  в топик-канал — так прогресс виден всем в общем чате, а подробная личная
  статистика остаётся только в личке у самого HR.

## Самозапись кандидатов + модерация

Любой пользователь бота видит в главном меню кнопку «📝 Оставить заявку» и
может сам заполнить анкету (имя и возраст, телефон, юзернейм, желаемое время
собеседования). Заявка со статусом «на модерации» уходит в топик-канал с
кнопками «✅ Одобрить» / «❌ Отклонить» — нажать их может любой HR или
админ (проверка прав — прямо в обработчике этой кнопки, не через фильтр
роутера, иначе HR не смог бы модерировать). При одобрении заявка становится
обычной записью и засчитывается тому, кто её одобрил.

## Про поиск в Telegram по номеру телефона

Сознательно не стал это делать. Bot API не даёт способа получить id
аккаунта по чужому номеру телефона — это ограничение самого Telegram, а не
библиотеки aiogram. Единственный обходной путь — `contacts.importContacts`
из клиентского (MTProto) API, то есть через юзер-аккаунт вместо бота, а это
ровно тот механизм, которым пользуются для пробива номеров и деанона;
Telegram активно банит за него аккаунты. Вместо этого юзернейм кандидата
просто необязателен (можно отправить `-` при заполнении), а дозаполнить его
позже можно через редактирование записи.

## Обратная совместимость данных

Если бот уже работал по предыдущей версии, при первом запуске после этого
обновления:
- старые id из `data/hr_roles.pkl` автоматически переносятся в новый
  `data/hr_profiles.pkl` (дата присоединения проставится текущим моментом,
  так как раньше она не хранилась);
- старые записи без `hr_id` / `interview_datetime` продолжают отображаться
  (со значением «—» там, где новых полей не было) и не ломают таблицу и
  список записей, но не попадают в личную статистику конкретного HR, пока
  вы не отредактируете их вручную через «✏️ Все записи».

## Хранение данных

Все данные лежат в папке `data/` в виде pickle-файлов:
- `users.pkl` — все, кто писал `/start`
- `hr_profiles.pkl` — HR: роль, дата присоединения, смены, отработанное время
- `hr_records.pkl` — записи (включая заявки на модерации)
- `settings.pkl` — выбранный топик для уведомлений, план на день
- `topics.pkl` — обнаруженные топики

Папка и файлы создаются автоматически при первом запуске/записи, вручную
ничего готовить не нужно. `data/` и `.env` исключены из git и из Docker-сборки
через `.gitignore` / `.dockerignore`.
